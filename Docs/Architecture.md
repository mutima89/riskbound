# Architecture

## Layers
```
UMG widgets / Blueprints (presentation, level scripting)
        |  read view-models, send player intents
Riskbound module (UE): ARbCharacter, URbInteractionComponent, ARbInteractable,
        URbGameSubsystem (owns rb::GameState), URbSaveSubsystem, mission director
        |  plain C++ calls, no UObjects below this line
RiskboundSim module (C++17, deterministic, unit tested outside UE)
```

## RiskboundSim (done, tested)
| File | Responsibility |
|---|---|
| `RbRng.h` | Seeded xoshiro256** RNG: uniform, normal, lognormal, Poisson |
| `RbRiskModel` | Matrix, control assessment, residual, appetite, risk register CRUD/filter/search |
| `RbQuant` | Expected loss, ALE, cost-benefit/NPV/ROI, KRIs, sensitivity, stress, Monte Carlo |
| `RbCareer` | Ladder, competencies, promotion gates, pathways |
| `RbOrganization` | Metrics, departments, three profiles, decision records, deferred consequences |
| `RbMission001` | Mission 001 content, objectives, hidden rubric, debrief, consequences |
| `RbJson`, `RbMissionData` | Strict JSON reader; mission files (`Data/Missions/*.json`) to `MissionDef` with file/line errors (Docs/MissionData.md) |
| `RbCampaign` | Generic missions (content as `MissionDef`), validation, availability, scoring, cross-mission consequences, promotion review |
| `RbGameState` | Persistent state, new game, achievements |
| `RbSave` | Versioned checksummed saves, safe writes, backup recovery, migration |

## Riskbound UE module (Gate 1, implemented)
Every class is thin; anything rule-like calls RiskboundSim. UI is Slate built in C++ (no binary widget assets).
| Class / file | Responsibility |
|---|---|
| `URbPersonComponent`, `URbPersonAnimInstance` (World/RbPerson) | Every person in the office: native anim instance (crossfades, one-shot gestures, pinned walking loops, head/eye bones), face shapes (blinks, lip-sync, expressions), walking routes; presentation only |
| `URbGameSubsystem` | Owns `rb::GameState`. Mission actions (`TalkToManager`, `ViewEvidence`, `SubmitAssessment`, `MarkDebriefReceived`) and Blueprint-callable views (objectives, evidence, options, debrief, career, register entry, settings). Checkpoints `M001:start/met_manager/submitted/debriefed`. |
| `URbSaveSubsystem` | `rb::SaveGameToFile`/`LoadGameFromFile` at `Saved/SaveGames/<slot>.rbsave` (default `slot1`). Autosave after meeting the manager, after submit, after the debrief. Reports backup recovery to the player. |
| `ARbCharacter` | First-person pawn. Enhanced Input actions + mapping context created in code: Move (WASD/arrows), Look (mouse, sensitivity from settings), Interact (E/Enter), Pause (Esc/P), Journal (J/Tab). |
| `URbInteractionComponent` | 3 m view trace, focus highlight, prompt text. |
| `ARbInteractable` + `ARbEvidenceProp`, `ARbWorkstation`, `ARbNpc` | Carry an id; `Interact` forwards to `ARbHUD`, which calls the subsystem. |
| `ARbValtrenHQ` | Graybox HQ built at runtime: seven labelled rooms off a corridor, lights, furniture, Mission 001 interactables. |
| `ARbGameMode` | Spawns the HQ and player start; starts `-RbSelfTest`. |
| `ARbHUD` + `UI/` | Screen flow: HUD overlay, main menu (difficulty, Continue), pause, settings, journal, workstation, document viewer, dialogue, assessment form, debrief. One modal screen at a time; Esc goes back; keyboard focus set on open. |
| `UI/SRbCaseFiles` | Case files screen: mission list with open/closed reasons and promotion gaps, mission (briefing, evidence, questions), debrief (criteria, consequences, promotion) |
| `URbCampaignSubsystem` | Gate 3 campaign: mission list with availability reasons, mission view (briefing incl. carry-over notes, evidence, questions without scores), start/evidence/submit, debrief with consequences and the promotion review. Thin calls into `RbCampaign`. Loads and validates `Data/Missions` at startup. |
| `URbToolsSubsystem` + `UI/SRbToolHub` | Gate 2 workstation tool hub: register (filter, search, create/edit, residual heatmap, appetite), KRI dashboard (status, sparkline, escalation), loss scenarios (EL with worst case, save to register), cost-benefit, NPV tornado, stress presets/custom, Monte Carlo (median/P90 fit, seed, percentiles, histogram), action tracker (start/close with evidence, advance a week), executive report (view, export to `Saved/Reports/*.md`). Thin view models over RiskboundSim; quant tools use only the player's inputs. |
| `RbSelfTest` | `-RbSelfTest=play` / `-RbSelfTest=resume` packaged-build check through the same HUD/interactable calls the UI uses (slot `selftest`). |
| `Private/Tests` | Automation tests `Riskbound.*`. |

Level: `Content/Maps/L_ValtrenHQ.umap` is an empty map (created by `Scripts/CreateMap.bat`); the HQ is generated by `ARbValtrenHQ`, so layout changes are code-reviewable.
Export: sim headers mark their API with `RB_API` (`RbApi.h`) because RiskboundSim is a separate DLL in editor builds.

## Determinism
All randomness flows from `GameState.Seed`. Organisation events re-derive each draw from `(EventSeed, EventDraws)`, so saving mid-scenario and resuming gives the same outcomes (`Save_ResumeContinuesSameRandomSequence`).

## Data
Mission 001 content is in C++ tables in `RbMission001.cpp` for now. Gate 4 moves mission content to Data Assets / validated data files under `Data/` with a schema validator test.
